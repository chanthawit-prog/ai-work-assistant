## ปัญหาที่พบและแก้แล้ว

1. **รัน Python ไม่ได้เมื่อ Claude ใช้ `cd ... && python3 ...`** — กฎเดิมอนุญาตเฉพาะ `Bash(python3 *)`
   แต่ Claude Code ตรวจสิทธิ์ทีละส่วนของคำสั่งที่ต่อกันด้วย `&&` จึงเพิ่ม `Bash(cd *)` และบอกใน prompt ว่ารันจากโฟลเดอร์งานได้เลย
   ทดสอบซ้ำแล้วผ่าน
2. **path ยาวบน timeline** — ย่อเป็น `knowledge/...` และ "โฟลเดอร์งาน" ทั้งในการอ่านไฟล์และในคำสั่งที่รัน
3. **งานที่สร้างผ่าน API โดยไม่ใส่ชื่อ** ได้ชื่อเป็นชนิดงาน ตอนนี้ใช้บรรทัดแรกของข้อความเหมือนหน้าเว็บ

## รอบที่ 3: Docker image จริง และการค้นคลังความรู้

**Docker** (dockerd 29 บนเครื่องทดสอบ cgroup v1 แบบเดียวกับ DSM 7.2)
- build จาก `Dockerfile` ของ repo ได้ใน 31 วินาที image 652 MB มี Claude Code 2.1.316 (native binary จาก npm), ฟอนต์ Anuphan,
  pec_calc และ Python package ครบ ข้อจำกัด: เครื่องทดสอบเข้า mirror ของ Debian ไม่ได้ (policy ของ network ปฏิเสธ) จึงใช้ base image
  ที่มีสิ่งที่ `apt-get` ติดตั้งอยู่แล้วแทน บรรทัด `apt-get` บรรทัดเดียวจึงยังไม่ได้ทดสอบ
- รันผ่าน `docker-compose.yml` และ `.env` จาก `.env.example` ได้: เพดาน RAM 1.5 GB และ swap เท่ากัน, `oom_score_adj` 500,
  `knowledge` เป็นแบบอ่านอย่างเดียว (เขียนไม่ได้จริง), รหัสผ่าน dashboard ทำงาน (`/healthz` ยังเข้าได้), healthcheck ขึ้น healthy
- dashboard ว่าง ๆ ใช้ RAM 43 MB ตัวเลขในหน้าระบบตรงกับ `docker stats`
- ทดสอบเพดานจริง: container เพดาน 200 MB กับงานที่จอง RAM 400 MB kernel หยุดเฉพาะตัว CLI (exit −9) dashboard ยังทำงาน
  ตัวนับ OOM ของ container เพิ่ม และงานขึ้นข้อความ "ใช้ RAM ครบเพดานของ container (เพดาน 200 MB)"

**ปัญหาที่พบจาก Docker และแก้แล้ว**
1. ไฟล์ JSON ทุกไฟล์ (เช่น `job.json`) ถูกสร้างเป็นสิทธิ์ 0600 ของ root ซึ่ง File Station อาจเปิดไม่ได้ ตอนนี้เป็น 0644
2. ก่อนล็อกอิน หน้าแรกบอกว่า "งานที่สั่งจะรอในคิวจนกว่าจะเชื่อมเสร็จ" แต่งานกลับล้มทันทีด้วยข้อความภาษาอังกฤษ
   "Not logged in · Please run /login" ตอนนี้งานรอในคิวจริง เริ่มเองหลังล็อกอิน และถ้าหมดอายุระหว่างใช้งานจะขึ้นคำแนะนำภาษาไทย
3. ข้อความ OOM เคยบอก "ใช้ไปสูงสุด 15 MB" เพราะ RAM พุ่งแล้วถูกหยุดระหว่างการวัดสองครั้ง ตอนนี้บอกเพดานของ container แทน
