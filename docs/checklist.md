# Checklist: วันติดตั้ง และวันแรกที่ใช้งาน (DS925+)

พิมพ์หน้านี้หรือเปิดคู่กับ [setup-ds925.md](setup-ds925.md) ทำทีละข้อตามลำดับ ทุกข้อมี "ตรวจอย่างไร" เพื่อให้รู้ว่าผ่านแล้วก่อนไปข้อถัดไป
ใช้เวลาราว 1–2 ชั่วโมงสำหรับวันติดตั้ง (ไม่รวมเวลา build image ครั้งแรก 5–15 นาที)

## ก. เตรียมก่อนวันติดตั้ง

- [ ] บัญชี Claude แบบ Pro, Max หรือ seat ของ Team/Enterprise และล็อกอินที่ claude.ai ได้ (ใช้ล็อกอินในข้อ 5)
- [ ] NAS: DSM 7.2 ขึ้นไป ติดตั้งแพ็กเกจ **Container Manager** แล้ว และทราบ IP ของ NAS ในวง LAN (เช่น 192.168.1.20)
- [ ] RAM ว่างของ NAS อย่างน้อย 1 GB ตอนไม่มีงาน (ดู Resource Monitor) ถ้า swap เต็มเป็นประจำ อ่านคู่มือข้อ 13 ก่อน
- [ ] โค้ดระบบ: ดาวน์โหลด ZIP จาก GitHub (หรือ `git clone`) ไว้ในคอมพิวเตอร์ที่จะอัปโหลด
- [ ] รหัสผ่าน dashboard ที่จะตั้ง (อย่างน้อย 12 ตัวอักษร) เก็บไว้ในที่เก็บรหัสผ่านของบริษัท
- [ ] เอกสารชุดแรกสำหรับคลังความรู้: price list ปัจจุบัน (xlsx/csv), profile ลูกค้า 2–3 ราย, design guide ที่มีสิทธิ์ใช้, ตารางสายของบริษัท (ถ้ามี)
- [ ] (ถ้าจะส่งอีเมลจากระบบ) บัญชีอีเมลของบริษัทที่ใช้ส่ง และ app password (Gmail/Microsoft 365 ดูคู่มือข้อ 8.2)
- [ ] (ถ้าจะใช้แจ้งเตือน) Webhook ของ Synology Chat หรือ token ของ LINE Messaging API (คู่มือข้อ 8)
- [ ] ผู้ที่จะใช้งานรู้กติกา 3 ข้อ: ทุกงานต้องกดอนุมัติก่อนนำไปใช้ · งานวิศวกรรมต้องให้วิศวกรผู้มีใบอนุญาตตรวจ · ไม่วางเอกสารที่ขัด NDA หรือมีข้อมูลส่วนบุคคลเกินจำเป็น

## ข. วันติดตั้ง

| # | ทำ | ตรวจอย่างไร |
|---|---|---|
| 1 | สร้าง shared folder `ai-assistant` และโฟลเดอร์ย่อย `data` `knowledge` `claude-home` (คู่มือข้อ 1) | File Station เห็นทั้ง 3 โฟลเดอร์ |
| 2 | อัปโหลดโค้ดไว้ที่ `/docker/ai-work-assistant` (คู่มือข้อ 2) | ในโฟลเดอร์มี `docker-compose.yml` `Dockerfile` และโฟลเดอร์ `app` |
| 3 | คัดลอก `.env.example` เป็น `.env` แก้ `DATA_PATH` `KNOWLEDGE_PATH` `CLAUDE_HOME_PATH` และตั้ง `DASHBOARD_PASSWORD` (คู่มือข้อ 3) ปล่อย `CLAUDE_BIN=claude` | เปิดไฟล์ดูอีกครั้งว่าทั้ง 3 path ชี้ไปโฟลเดอร์จากข้อ 1 และไม่มีช่องว่างท้ายบรรทัด |
| 4 | Container Manager → Project → Create ชี้ไปโฟลเดอร์โค้ด แล้วรอ build (คู่มือข้อ 4) | Project ขึ้นสถานะ Running และ container `ai-work-assistant` เป็น healthy |
| 5 | ล็อกอิน Claude ใน container ผ่าน SSH: `sudo docker exec -it ai-work-assistant claude auth login` (คู่มือข้อ 5) แล้วปิด SSH | `sudo docker exec ai-work-assistant claude auth status --text` บอกว่า logged in |
| 6 | เปิด `http://<IP>:8080` ใส่ user `admin` กับรหัสผ่านจากข้อ 3 | ป้ายมุมขวาบนเป็นสีเขียว "Claude พร้อม" |
| 7 | หน้า **ระบบ → ความพร้อมของระบบ** (คู่มือข้อ 6.1) | ไม่มีข้อที่เป็น ✗ ข้อ ! ที่เหลือควรเป็นแค่เรื่องที่ตั้งใจเว้นไว้ (เช่น แจ้งเตือน) |
| 8 | วางคลังความรู้: คัดลอกโฟลเดอร์ `examples/knowledge/` ทั้งหมดไปที่ `knowledge/` แล้วแทนไฟล์ตัวอย่างด้วยของจริงจากข้อ ก. (คู่มือข้อ 7 และ README ในโฟลเดอร์ตัวอย่าง) | หน้า **ลูกค้า** เห็นลูกค้าที่ใส่ไว้ และ **ระบบ → คลังความรู้** หลังกด "อัปเดตดัชนีตอนนี้" บอกจำนวนไฟล์ครบ รายการ "ไฟล์ที่อ่านไม่ได้" ว่าง |
| 9 | ทดสอบงานแรก: หน้าแรก → งานทั่วไป → "สรุปสั้น ๆ ว่าคุณช่วยงานอะไรได้บ้าง" | timeline ขยับ งานขึ้น "ผลงานพร้อมให้ตรวจ" ภายในราว 1 นาที กด **อนุมัติผลงาน** แล้วไฟล์ Word โผล่ใน `data/library/general/` |
| 10 | (ถ้าใช้) ตั้งอีเมลใน `.env` (คู่มือข้อ 8.2) → Build ใหม่ → **ระบบ → ส่งอีเมลทดสอบถึงตัวเอง** | อีเมลทดสอบเข้ากล่องของบัญชีที่ตั้งไว้ |
| 11 | (ถ้าใช้) ตั้งแจ้งเตือน `DASHBOARD_URL` + ช่องทาง (คู่มือข้อ 8) → Build ใหม่ → **ระบบ → ส่งข้อความทดสอบ** | ข้อความทดสอบเข้า Synology Chat หรือ LINE และลิงก์ในข้อความเปิดได้ |
| 12 | เปิด Snapshot ให้ shared folder และตั้ง Hyper Backup สำหรับ `data/` กับ `knowledge/` (คู่มือข้อ 12) | Snapshot แรกถูกสร้าง และงาน backup อยู่ในตาราง |
| 13 | มือถือ: เพิ่มไอคอนลงหน้าจอ (คู่มือข้อ 11.1) และตั้ง VPN/Tailscale ถ้าจะใช้นอกออฟฟิศ (ข้อ 10) อย่า forward port 8080 ออกอินเทอร์เน็ต | เปิดจากมือถือได้ ป้ายเขียวเหมือนบนคอม |
| 14 | ตรวจความพร้อมซ้ำอีกครั้ง (ข้อ 7) และบันทึกวันที่ติดตั้งกับเวอร์ชัน (หน้าระบบ → ที่เก็บข้อมูล → เวอร์ชัน) | จดไว้ในบันทึกของบริษัท |

## ค. วันแรกที่ใช้จริง (ทีละข้อ ใช้โควต้าเล็กน้อย)

- [ ] **ถาม** 1 คำถามจากเอกสารที่วางไว้ เช่น "ราคา MCCB 125A เท่าไหร่" → คำตอบมีเลขอ้างอิง [1] ชี้ไปไฟล์ที่ถูกต้อง
- [ ] **สรุปประชุม** 1 ไฟล์ (transcript จาก Teams/Zoom หรือ Word) → ตรวจ action item ที่ขึ้นในหน้า **ติดตามงาน** แก้ผู้รับผิดชอบและกำหนดเสร็จให้ถูก
- [ ] ปล่อยให้งาน **ติดตามงาน** อัตโนมัติทำงานตอนเช้าวันถัดไป (`FOLLOWUP_TIME` ค่าตั้งต้น 08:00) → ดูว่าร่างข้อความติดตามใช้ได้ และเตรียมพิมพ์ "ทำงานต่อ" เมื่อต้องการ
- [ ] **ร่างใบเสนอราคา** 1 ฉบับจากคำขอจริง → ตรวจราคาทุกบรรทัดกับ price list → **แก้ไขเอง** ถ้าจำเป็น → อนุมัติ → **ส่งอีเมล** ถึงตัวเองก่อนส่งลูกค้าจริง
- [ ] แนบ **PDF ที่สแกน** 1 ไฟล์กับงานทั่วไป → หน้างานขึ้นขั้นตอน OCR และผลลัพธ์บอกจุดที่อ่านไม่ชัด
- [ ] ดู **ระบบ → หน่วยความจำ** หลังงานแรก ๆ: RAM สูงสุดต่องานควรอยู่ราว 200–300 MB ถ้าเกิน 1 GB หรือ NAS ช้า อ่านคู่มือข้อ 13
- [ ] ตั้งงานประจำที่ต้องการในหน้า **งานประจำ** (เช่น สรุปงานทุกวันศุกร์) และดูว่าไม่ชนกับเวลางานติดตาม

## ง. สิ่งที่ต้องรู้ตลอดการใช้งาน

- ระบบไม่ส่งอะไรออกไปเอง: อีเมลส่งเฉพาะที่คุณกดยืนยัน แจ้งเตือนมีแค่ชื่องานและลิงก์ ข้อมูลที่ Claude อ่านอยู่ภายใต้เงื่อนไขของแพ็กเกจ Claude ที่ใช้
- ผลงานที่ Claude เขียนเป็น "ฉบับร่าง" จนกว่าจะกดอนุมัติ ราคา พิกัด และข้อกำหนดต้องตรวจกับต้นฉบับ โดยเฉพาะที่มาจาก OCR
- อัปเดตระบบ: อัปโหลดโค้ดใหม่ทับแล้ว Build (คู่มือข้อ 11) จากนั้นเปิดหน้าระบบตรวจความพร้อมทุกครั้ง
- เมื่อมีปัญหา เริ่มจากตาราง "แก้ปัญหา" ท้ายคู่มือ และ Container Manager → Container → Log
